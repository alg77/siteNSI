Le labyrinthe : pile ou file ?

Parcours en profondeur (pile) et en largeur (file)

⏱ 2 h

  • Utiliser un dictionnaire pour mémoriser les cases vues et leur case « parente ».
  • Reconstruire un chemin, comparer parcours en profondeur (DFS) et en largeur (BFS).
  • Faire le lien avec les graphes (chapitre suivant) : une grille est un graphe.

Sortir du labyrinthe

Un labyrinthe est une grille de caractères : # est un mur, un espace est une case libre, S est le départ et E l'arrivée.

#####
#S  #      grille[y][x]  → le caractère de la colonne x, ligne y
# # #      la case S est (1, 1) et E est (3, 3)
#  E#
#####

Une case est un couple (x, y) : x est la colonne, y la ligne (0 en haut). On accède à un caractère par grille[y][x]. On se déplace en haut, bas, gauche, droite (pas en diagonale).

Un seul algorithme, deux structures

On garde une structure de cases à explorer. À chaque étape, on en retire une, on ajoute ses voisins non encore vus. Seul le choix de la structure change tout :

StructureOn explore…Parcours
Pile (LIFO)toujours la case la plus récemment découverte : on fonce tout droit, puis on revient en arrièreen profondeur (DFS)
File (FIFO)les cases dans l'ordre de découverte : couche par couche autour du départen largeur (BFS)

Pseudo-code commun :

structure ← vide ; on y met depart
parents ← {depart : None}         # dictionnaire : case -> case d'où l'on vient (sert aussi à savoir si une case est déjà vue)
visites ← liste vide
tant que la structure n'est pas vide :
    c ← on retire une case
    on l'ajoute à visites
    si c est l'arrivée : on s'arrête
    pour chaque voisin v de c :
        si v n'est pas dans parents :
            parents[v] ← c ; on met v dans la structure

La fonction creer_labyrinthe(largeur, hauteur, graine, boucles) (fournie) génère un labyrinthe reproductible (même graine, même labyrinthe) ; trouver(grille, "S") renvoie la case du départ (idem avec "E").
