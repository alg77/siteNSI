Bases de données

Modèle relationnel, contraintes d'intégrité, SGBD, langage SQL

SQL Relationnel SGBD

🎯 Introduction

Une base de données (BDD, database) est un ensemble organisé de données (nombres, textes, dates…) que l'on peut stocker, recouper et interroger par des moyens informatiques pour produire de l'information. Dans une base de données relationnelle, les données sont rangées dans des tables (relations) reliées entre elles par des clés. On les manipule avec le langage SQL, via un logiciel appelé SGBD.

🤔

Activité d'accroche — la bibliothèque du village

Une petite bibliothèque d'Ardèche gère ses prêts sur fiches papier et est débordée. Son seul outil : un tableur, sans Internet. Contraintes : un livre est emprunté puis rendu par un lecteur à une date précise, un lecteur doit être identifié à coup sûr, un livre peut avoir plusieurs auteurs et un auteur plusieurs livres.

① Propose une organisation du tableur pour enregistrer livres, auteurs, prêts et retours. Est-elle facile à utiliser ? ② Que se passe-t-il si un second bibliothécaire arrive, sur le même PC ? sur un autre PC ?

👉 On met en évidence les limites d'un tableur ou d'un fichier CSV : redondance (le nom d'un auteur recopié à chaque livre), incohérences (fautes de frappe, lecteurs homonymes), accès simultanés impossibles, pas de contrôle des saisies. C'est exactement ce que résolvent le modèle relationnel et les SGBD.

✅ Ce qu'il faut savoir (programme officiel de Terminale)

  • Modèle entité-association (entités, associations, cardinalités) et sa traduction en modèle relationnel
  • Modèle relationnel : relation, attribut, domaine, clé primaire, clé étrangère, schéma relationnel
  • Distinguer la structure d'une base (les schémas) de son contenu (les lignes)
  • Repérer des anomalies dans le schéma d'une base : redondance, anomalies d'insertion, de suppression, de mise à jour
  • Les services rendus par un SGBD : persistance, gestion des accès concurrents, efficacité des requêtes, sécurisation des accès
  • Identifier les composants d'une requête et écrire des requêtes avec SELECT, FROM, WHERE, JOIN
  • Utiliser DISTINCT, ORDER BY et les fonctions d'agrégation COUNT, SUM, AVG, MIN, MAX
  • Regrouper des lignes avec GROUP BY et filtrer les groupes avec HAVING
  • Écrire des requêtes de mise à jour : INSERT, UPDATE, DELETE
📏

Les sujets rappellent en général les mots-clés SQL autorisés dans l'énoncé. Pour les jointures, seul JOIN … ON est utilisé et exigible ; une même requête peut contenir plusieurs JOIN. Notation d'un schéma relationnel

Le nom de la relation est en gras, la clé primaire est soulignée, une clé étrangère est précédée d'un dièse #.

Lecteur (Num_SS, Nom_lecteur, Prenom_lecteur, Age)
Livre (Isbn, #Num_SS, Titre, Annee, Prix)
Auteur (Id_auteur, Nom_auteur, Prenom_auteur, Nationalite)
Ecrire (#Isbn, #Id_auteur, Nb_chapitres)
  • Num_SS (numéro de sécurité sociale) est unique pour chaque personne : c'est une bonne clé primaire pour Lecteur. Pour Auteur, on crée un identifiant artificiel Id_auteur.
  • Un livre est emprunté par au plus un lecteur à la fois : on ajoute la clé étrangère Num_SS dans Livre (NULL si le livre est disponible).
  • Un livre peut avoir plusieurs auteurs et un auteur plusieurs livres : on ne peut pas mettre une seule clé étrangère d'un côté sans créer de doublons. On crée donc une relation d'association Ecrire, dont la clé primaire est le couple (Isbn, Id_auteur).
🧱

Structure ≠ contenu

La structure d'une base, c'est l'ensemble de ses schémas relationnels (les noms de tables, d'attributs, les domaines, les clés) : elle change rarement. Le contenu, ce sont les lignes : il change à chaque emprunt. CREATE TABLE décrit la structure ; INSERT, UPDATE, DELETE modifient le contenu.

Le modèle entité-association

Avant de créer les tables, on conçoit la base avec un schéma indépendant de toute considération informatique : le modèle entité-association (on parle aussi de modèle conceptuel des données, MCD).

NotionDéfinitionExemple
EntitéObjet que l'on peut identifier distinctement (une personne, un livre, une réservation…), représenté par un rectangleLecteur, Livre, Auteur
AttributPropriété qui décrit une entité (ou une association)Titre, Annee
IdentifiantAttribut(s) qui distinguent chaque entité des autres (souligné)Isbn pour Livre
AssociationLien entre entités, représenté par une ellipse ; elle peut porter des attributsEmprunter, Ecrire (avec Nb_chapitres)
CardinalitéCouple (min, max) écrit côté entité : combien de fois au minimum et au maximum une entité participe à l'associationUn lecteur emprunte entre 0 et n livres → (0, n)
  • Emprunter : un lecteur emprunte de 0 à n livres → (0, n) ; un livre est emprunté par 0 ou 1 lecteur à la fois → (0, 1).
  • Ecrire : un livre est écrit par 1 à n auteurs → (1, n) ; un auteur a écrit 1 à n livres → (1, n). L'association porte l'attribut Nb_chapitres (nombre de chapitres écrits par cet auteur dans ce livre).

Du modèle entité-association au modèle relationnel

🔁

Règles de passage

  1. Chaque entité devient une relation ; son identifiant devient la clé primaire.
  2. Association avec une cardinalité maximale 1 d'un côté (« un à plusieurs ») : on ajoute une clé étrangère dans la relation du côté du 1. Ici Livre reçoit #Num_SS.
  3. Association avec des cardinalités maximales n des deux côtés (« plusieurs à plusieurs ») : elle devient une relation dont la clé primaire est le couple des deux clés étrangères, avec ses éventuels attributs. Ici Ecrire(#Isbn, #Id_auteur, Nb_chapitres).
Modèle entité-associationModèle relationnel
RôleConcevoir : décrire le monde réelImplémenter : décrire les tables du SGBD
ReprésentationDiagramme : rectangles, ellipses, cardinalitésListe de schémas : Livre(Isbn, #Num_SS, …)
LiensAssociations avec cardinalitésClés étrangères (et relations d'association)
Au bacParfois fourni pour être lu ou traduitLe plus souvent demandé : lire, compléter, corriger un schéma

On distingue ainsi trois niveaux de conception : conceptuel (entité-association), logique (schéma relationnel) et physique (création des tables dans un SGBD avec CREATE TABLE).

🔒 Contraintes d'intégrité et anomalies

Une base relationnelle doit garantir la fiabilité de ses données. Le modèle relationnel permet d'exprimer des contraintes d'intégrité, que le SGBD vérifie à chaque modification : toute opération qui les violerait est refusée.

ContrainteRègleExemple
Contrainte de relation (ou d'entité)La clé primaire est unique et jamais NULL : deux lignes ne peuvent pas avoir la même cléImpossible d'insérer deux livres avec le même Isbn
Contrainte de référence (intégrité référentielle)Une clé étrangère doit correspondre à une clé primaire existante (ou être NULL)Impossible d'attribuer un livre à un Num_SS absent de Lecteur ; impossible de supprimer un lecteur qui a encore un livre
Contrainte de domaineChaque valeur appartient au domaine de son attributNum_SS : entier de 15 chiffres ; 'nicolaigogol' est refusé
Contrainte utilisateur (métier)Règle propre à l'applicationUn âge est compris entre 0 et 130 ; un prix est positif

En SQL, ces contraintes s'écrivent dans la définition des tables. Il faut savoir les lire :

CREATE TABLE Livre (
  Isbn   INTEGER,
  Num_SS INTEGER,
  Titre  TEXT NOT NULL,                              -- valeur obligatoire
  Annee  INTEGER,
  Prix   REAL,
  PRIMARY KEY (Isbn),                                -- contrainte de relation
  FOREIGN KEY (Num_SS) REFERENCES Lecteur(Num_SS),   -- contrainte de référence
  CHECK (LENGTH(Isbn) = 13),                         -- contrainte de domaine
  CHECK (Annee BETWEEN -2000 AND 2100)
);
Mot-clé SQLEffet
PRIMARY KEYClé primaire : unique et non NULL
FOREIGN KEY … REFERENCES …Clé étrangère vers la clé primaire d'une autre table
NOT NULLLa valeur ne peut pas être absente
UNIQUEDeux lignes ne peuvent pas avoir la même valeur
CHECK (condition)Chaque ligne doit vérifier la condition (domaine ou règle métier)
Types SQLiteINTEGER, REAL, TEXT (les dates sont souvent stockées en texte 'AAAA-MM-JJ')

Repérer des anomalies dans un schéma

Un schéma mal conçu stocke la même information à plusieurs endroits : c'est la redondance. Exemple d'une table unique « tout-en-un » :

IsbnTitreNom_auteurNationalite
9782070360024L'étrangerCamusFrançaise
9782070360420La pesteCamusFrançaise
9782876470194La géométrieDescartesFrancaise
  • Anomalie de mise à jour : pour corriger la nationalité de Camus, il faut modifier toutes ses lignes ; en oublier une rend la base incohérente (et une faute de frappe comme « Francaise » passe inaperçue).
  • Anomalie d'insertion : impossible d'enregistrer un auteur tant qu'on n'a aucun de ses livres (la clé Isbn serait vide).
  • Anomalie de suppression : supprimer le seul livre de Descartes efface aussi toute trace de l'auteur.

👉 Le remède : découper en plusieurs relations (Livre, Auteur, Ecrire) reliées par des clés étrangères, pour que chaque information ne soit stockée qu'une seule fois.

⚙️ Système de gestion de bases de données (SGBD)

Un SGBD est le logiciel qui gère la base : il stocke les données, exécute les requêtes SQL et fait respecter les contraintes. Il cache la complexité du stockage (fichiers, disques) et offre une vue synthétique des données. Exemples de SGBD relationnels (SGBDR) : SQLite, MySQL/MariaDB, PostgreSQL, Oracle, Microsoft SQL Server. Aucun n'est à connaître en particulier.

Service renduCe que ça signifieExemple concret
💾 Persistance des donnéesLes données survivent à l'arrêt du programme ou de la machine (stockage sur disque), et le système peut retrouver un état cohérent après une panneAprès une coupure de courant, les prêts enregistrés sont toujours là
👥 Gestion des accès concurrentsPlusieurs utilisateurs peuvent lire et modifier la base en même temps sans la corrompreDeux bibliothécaires ne peuvent pas prêter le même exemplaire au même instant

🔁

Transactions (culture générale)

Une transaction est une suite d'opérations traitée comme un tout. Exemple : un virement bancaire, c'est débiter un compte et créditer l'autre. Le SGBD garantit les propriétés ACID : Atomicité (tout ou rien), Cohérence (les contraintes restent vérifiées), Isolation (les transactions simultanées ne se gênent pas), Durabilité (une fois validée, la transaction n'est jamais perdue). Il n'est pas demandé d'expliquer comment le SGBD y parvient, mais de comprendre pourquoi c'est indispensable.

🔎 SQL — Interroger une table

Une requête d'interrogation renvoie toujours… une table (le résultat). Sa structure de base :

SELECT attribut1, attribut2   -- quelles colonnes ? (* = toutes)
FROM   Table                  -- dans quelle table ?
WHERE  condition              -- quelles lignes ? (facultatif)
ORDER BY attribut ASC;        -- dans quel ordre ? (facultatif, DESC = décroissant)

Les mots-clés s'écrivent par convention en MAJUSCULES, les noms de tables et d'attributs sans espace ni accent. Les chaînes de caractères sont entre apostrophes : 'Camus' (une apostrophe dans le texte se double : 'L''étranger').

-- Toutes les colonnes de tous les livres
SELECT * FROM Livre;

-- Titre et année des livres parus après 1900, du plus récent au plus ancien
SELECT Titre, Annee
FROM Livre
WHERE Annee > 1900
ORDER BY Annee DESC;

-- Livres qui ne sont pas empruntés (attention : IS NULL, jamais = NULL)
SELECT Titre FROM Livre WHERE Num_SS IS NULL;

-- Lectrices : le numéro de sécurité sociale commence par 2
SELECT Nom_lecteur, Prenom_lecteur
FROM Lecteur
WHERE Num_SS LIKE '2%';

-- Nationalités des auteurs, sans doublon
SELECT DISTINCT Nationalite FROM Auteur;

-- Renommer une colonne du résultat avec AS
SELECT Titre AS Ouvrage, Annee AS Parution FROM Livre WHERE Annee < 1800;

AND, OR, NOTOpérateurs booléens (parenthèses conseillées)Age >= 18 AND Age < 30

LIMIT n (garder les n premières lignes) existe en SQLite et apparaît parfois dans les sujets, mais n'est pas exigible.

📊 Fonctions d'agrégation et regroupements

Une fonction d'agrégation résume plusieurs lignes en une seule valeur. Le résultat de la requête n'a alors qu'une seule ligne.

FonctionRenvoie
COUNT(*)le nombre de lignes
COUNT(attribut)le nombre de valeurs non NULL de l'attribut
COUNT(DISTINCT attribut)le nombre de valeurs différentes
SUM(attribut), AVG(attribut)la somme, la moyenne (les NULL sont ignorés)
MIN(attribut), MAX(attribut)la plus petite, la plus grande valeur
-- Nombre de livres parus avant 1900
SELECT COUNT(*) AS Nb_anciens FROM Livre WHERE Annee < 1900;

-- Année du livre le plus récent et du plus ancien
SELECT MAX(Annee) AS Plus_recent, MIN(Annee) AS Plus_ancien FROM Livre;

-- Prix total des ouvrages payants (les livres gratuits ont un Prix NULL)
SELECT SUM(Prix) AS Prix_total FROM Livre;

-- Moyenne d'âge des lecteurs
SELECT AVG(Age) AS Moyenne FROM Lecteur;

-- Nombre de nationalités différentes parmi les auteurs
SELECT COUNT(DISTINCT Nationalite) FROM Auteur;
✍️ Compare COUNT(*) et COUNT(Prix) : pourquoi ces deux nombres sont-ils différents ?
🚨

Agrégats : trois règles

  • On ne met pas de fonction d'agrégation dans un WHERE : ❌ WHERE COUNT(*) > 3. Le WHERE filtre les lignes avant le calcul.
  • Sans GROUP BY, on ne mélange pas un agrégat et une colonne « normale » dans le SELECT : ❌ SELECT Titre, MAX(Annee).
  • COUNT(*) compte toutes les lignes, COUNT(attribut) ignore les NULL.

Regrouper : GROUP BY et HAVING Pour aller plus loin

GROUP BY attribut range les lignes en groupes qui ont la même valeur pour cet attribut, puis la fonction d'agrégation est calculée pour chaque groupe : le résultat a une ligne par groupe.

-- Nombre de livres écrits par des auteurs de chaque nationalité
SELECT Auteur.Nationalite, COUNT(*) AS Nb
FROM Ecrire
JOIN Auteur ON Ecrire.Id_auteur = Auteur.Id_auteur
GROUP BY Auteur.Nationalite;
NationaliteNb
Allemande1

HAVING condition filtre ensuite les groupes, alors que WHERE filtre les lignes avant le regroupement.

-- Marins ayant réservé au moins 3 fois
SELECT Marin.Mnom, COUNT(*) AS Nb_resa
FROM Marin
JOIN Reservation ON Marin.Mid = Reservation.Mid
GROUP BY Marin.Mid, Marin.Mnom
HAVING COUNT(*) >= 3;
⚙️

Ordre d'exécution d'une requête

FROM / JOIN (on construit la table) → WHERE (on garde des lignes) → GROUP BY (on forme les groupes) → HAVING (on garde des groupes) → SELECT (on calcule les colonnes) → ORDER BY (on trie). C'est pour cela qu'un agrégat ne peut pas figurer dans le WHERE, mais peut figurer dans le HAVING.

🚨

GROUP BY : deux règles

  • Dans le SELECT, on ne met que des attributs présents dans le GROUP BY et des fonctions d'agrégation.
  • ❌ WHERE COUNT(*) >= 3 → ✅ HAVING COUNT(*) >= 3. Une condition sur une ligne (Age > 18) va dans le WHERE.
✍️ À toi : le montant total de chaque commande (quantité × prix)

🔗 Jointures

💡

Principe

Quand l'information est répartie dans plusieurs tables, on les joint : chaque ligne de la première table est associée aux lignes de la seconde qui vérifient la condition ON. Presque toujours, cette condition relie une clé étrangère à la clé primaire qu'elle référence : ON Table1.fk = Table2.pk. Les lignes sans correspondance n'apparaissent pas dans le résultat.

-- Titre de chaque livre emprunté et nom de son emprunteur
SELECT Livre.Titre, Lecteur.Nom_lecteur
FROM Livre
JOIN Lecteur ON Livre.Num_SS = Lecteur.Num_SS;
-- Les livres non empruntés (Num_SS NULL) n'apparaissent pas.

-- Même requête avec des alias (plus courte). JOIN et INNER JOIN sont synonymes.
SELECT B.Titre, L.Nom_lecteur
FROM Livre AS B
JOIN Lecteur AS L ON B.Num_SS = L.Num_SS
ORDER BY L.Nom_lecteur;

-- Trois tables (donc deux JOIN) : les titres écrits par Camus
SELECT Livre.Titre
FROM Livre
JOIN Ecrire ON Livre.Isbn = Ecrire.Isbn
JOIN Auteur ON Ecrire.Id_auteur = Auteur.Id_auteur
WHERE Auteur.Nom_auteur = 'Camus';

-- Jointure + DISTINCT : les lecteurs ayant emprunté au moins un livre (chacun une seule fois)
SELECT DISTINCT Lecteur.Prenom_lecteur, Lecteur.Nom_lecteur
FROM Lecteur
JOIN Livre ON Lecteur.Num_SS = Livre.Num_SS;

-- Jointure + agrégat : nombre de livres actuellement empruntés par Germaine Michu
SELECT COUNT(*)
FROM Livre
JOIN Lecteur ON Livre.Num_SS = Lecteur.Num_SS
WHERE Lecteur.Nom_lecteur = 'Michu';
🚨

Préfixer les attributs

Si un attribut existe dans les deux tables (Num_SS, Isbn…), il faut écrire Table.attribut, sinon le SGBD signale une colonne ambiguë. Bonne habitude : préfixer toujours les attributs dès qu'il y a une jointure.

Tu rencontreras aussi l'ancienne syntaxe, sans JOIN, qu'il faut savoir lire : SELECT A.Nom_lecteur, B.Titre FROM Lecteur A, Livre B WHERE A.Num_SS = B.Num_SS; On privilégie JOIN … ON, plus lisible.

✍️ À toi : les titres empruntés par des lecteurs de moins de 30 ans

Les différents types de jointure Pour aller plus loin

Au bac, seul JOIN est utilisé et exigible (avec éventuellement plusieurs JOIN dans la même requête). Il existe pourtant d'autres jointures, qu'on rencontre dans les SGBD et dans le supérieur. Exemple : on joint Lecteur (10 lecteurs) et Livre (17 livres, dont 9 empruntés par 7 lecteurs différents) sur Num_SS.

JointureLignes gardéesNombre de lignes ici
JOIN = INNER JOINSeulement les couples qui se correspondent : les livres empruntés avec leur lecteur9
LEFT JOIN (LEFT OUTER JOIN)Toutes les lignes de la table de gauche (Lecteur), même sans correspondance ; les colonnes de droite valent alors NULL9 + 3 lecteurs sans livre = 12
RIGHT JOIN (RIGHT OUTER JOIN)Toutes les lignes de la table de droite (Livre), même sans correspondance9 + 8 livres non empruntés = 17
FULL OUTER JOINToutes les lignes des deux tables, avec des NULL là où il n'y a pas de correspondance9 + 3 + 8 = 20

JOIN tout court est donc un INNER JOIN : c'est la seule jointure à savoir écrire. Les mots OUTER (« externe ») désignent les jointures qui gardent aussi les lignes sans correspondance.

✏️ SQL — Mettre à jour les données

-- INSERT : ajouter une ou plusieurs lignes
INSERT INTO Lecteur (Num_SS, Nom_lecteur, Prenom_lecteur, Age)
VALUES (206077512398765, 'Benali', 'Sofia', 20);

-- UPDATE : modifier des valeurs ('Le gai savoir' est emprunté par Sofia Benali)
UPDATE Livre
SET Num_SS = 206077512398765
WHERE Isbn = 9781533468406;        -- on cible de préférence par la clé primaire

-- Retour du livre : il redevient disponible
UPDATE Livre SET Num_SS = NULL WHERE Isbn = 9781533468406;

-- DELETE : supprimer des lignes
DELETE FROM Lecteur WHERE Num_SS = 189029231941483;
🚨

Toujours un WHERE !

UPDATE Livre SET Annee = 2000; modifie tous les livres, et DELETE FROM Lecteur; vide toute la table. Avant un UPDATE ou un DELETE, teste ton WHERE avec un SELECT.

Le SGBD refuse toute mise à jour qui violerait une contrainte d'intégrité. Essaie ces requêtes et lis le message d'erreur :

🧭 Méthode bac

🪜

Écrire une requête en 6 questions

  1. Que dois-je afficher ? → les attributs du SELECT (ou un agrégat).
  2. Dans quelles tables se trouvent ces attributs et ceux des conditions ? → FROM.
  3. Plusieurs tables ? → je suis le chemin des clés étrangères sur le schéma : un JOIN … ON fk = pk par liaison (3 tables = 2 JOIN).
  4. Quelles lignes garder ? → WHERE (texte entre apostrophes, IS NULL pour l'absence).
  5. Un résultat « par » quelque chose ? → GROUP BY ; une condition sur un agrégat → HAVING (pour aller plus loin).
  6. Doublons ? Ordre ? → DISTINCT, ORDER BY … ASC/DESC.
✒️

Rédiger ses justifications

À l'écrit du bac (à partir de la session 2027), 2 points sur 20 évaluent la maîtrise de la langue : orthographe, syntaxe et vocabulaire précis. Les questions « Justifier », « Expliquer » attendent des phrases complètes qui utilisent le vocabulaire du cours.

❌ « Num_SS c'est la clé car c'est unique. »
✅ « L'attribut Num_SS peut servir de clé primaire de la relation Lecteur car deux lecteurs distincts ne peuvent pas avoir le même numéro de sécurité sociale. Dans la relation Livre, Num_SS est une clé étrangère qui fait référence à la clé primaire de Lecteur. »

🚨

Pièges SQL au bac

  • = NULL ne marche jamais : on écrit IS NULL / IS NOT NULL
  • Texte entre apostrophes 'Paris' ; nombres sans apostrophes
  • COUNT(*) compte toutes les lignes, COUNT(col) ignore les NULL ; SUM et AVG ignorent aussi les NULL
  • Pas d'agrégat dans un WHERE : une condition sur un agrégat va dans le HAVING
  • Avec GROUP BY, le SELECT ne contient que des attributs du GROUP BY et des agrégats
  • Une jointure ne garde que les lignes qui ont une correspondance : un livre non emprunté disparaît d'une jointure Livre–Lecteur
  • Attribut présent dans deux tables → le préfixer (Livre.Isbn)
  • Après une jointure, penser à DISTINCT si une même personne peut apparaître plusieurs fois
  • UPDATE / DELETE sans WHERE modifient toute la table
  • Ordre des clauses imposé : SELECT → FROM → JOIN … ON → WHERE → GROUP BY → HAVING → ORDER BY
  • SQL ne distingue pas majuscules et minuscules pour les mots-clés (SELECT = select), mais 'Camus' ≠ 'camus' dans les données

📌 Fiche synthèse

MODÈLE RELATIONNEL

  • Relation = table, attribut = colonne, tuple = ligne
  • Domaine = valeurs autorisées
  • PK unique et non NULL (soulignée)
  • FK → PK d'une autre table (#)
  • Structure (schémas) ≠ contenu (lignes)
  • Entité-association : entités, associations, cardinalités → relations

INTÉGRITÉ & SGBD

  • Contraintes de relation, de référence, de domaine
  • Redondance → anomalies d'insertion, de suppression, de mise à jour
  • SGBD : persistance, accès concurrents, efficacité, sécurité
  • Transaction : tout ou rien

INTERROGER

  • SELECT … FROM … WHERE … ORDER BY
  • DISTINCT, AS, LIKE, IN, BETWEEN, IS NULL
  • COUNT, SUM, AVG, MIN, MAX
  • Pour aller plus loin : GROUP BY + HAVING
  • JOIN … ON fk = pk (n tables = n−1 JOIN)

METTRE À JOUR

  • INSERT INTO T (a, b) VALUES (…)
  • UPDATE T SET a = … WHERE …
  • DELETE FROM T WHERE …
  • Le SGBD refuse ce qui viole une contrainte
